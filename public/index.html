    How it works
    
    
      
      
    1. On-chain facts — via public BSC RPC: is there code at this address? What are its name / symbol / decimals / supply? Who is the owner? Is it paused? Is it an EIP-1967 proxy, and is the implementation verified?
      2. 
      
    2. Source audit — via Sourcify: is the source verified? If yes, it is scanned for owner-mint, blacklist, adjustable fee/tax, pause and upgrade powers. If not, the bytecode is scanned for the same function selectors — flagged as uncertain, never as proof.
      3. 
      
    3. Sell simulation — via honeypot.is (tokens with a DEX pair only): does a simulated buy/sell succeed, and at what tax? The simulation outcome is trusted over the headline label, because the label has false positives on legitimate restricted tokens.
      4. 
      
    4. Scoring — each finding adds points (unverified source +30, owner-mint +35, confirmed honeypot +40, …) and trust findings subtract them (verified −10, clean simulation −5). Score < 30 → ALLOW, 30–64 → CAUTION, ≥ 65 → BLOCK. If an upstream is unreachable, MintGuard fails closed (CAUTION) instead of guessing.
      5. 
    
    
    
    ALLOW means "no specific risk was found" — it is not a guarantee of safety. A verified-looking contract can still be a scam. Never approve an unlimited spend you do not understand.
